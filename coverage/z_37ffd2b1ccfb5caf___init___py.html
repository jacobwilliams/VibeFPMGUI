1"""A desktop GUI for the Fortran Package Manager (fpm). 

2 

3> [!NOTE] 

4> These are the **API docs** for the `vibefpmgui` Python package, generated 

5> with [pdoc](https://pdoc.dev) from the docstrings in the source code. They 

6> describe the code; for what the app does and how to use it, see the 

7> [website](https://jacobwilliams.github.io/VibeFPMGUI/) or the 

8> [README](https://github.com/jacobwilliams/VibeFPMGUI#readme). 

9 

10VibeFPMGUI opens an `fpm.toml` and runs fpm's commands (build, run, test, 

11update, clean) with live progress, shows the project's dependencies as an 

12interactive graph, and has a built-in Fortran editor with a language server, 

13linting, formatting and an AI code reviewer that runs on your own computer. 

14It is written in Python with Qt (PySide6, through qtpy). 

15 

16*VibeFPMGUI is an experimental, vibe-coded project: expect rough edges.* 

17 

18## Links 

19 

20* **Website:** <https://jacobwilliams.github.io/VibeFPMGUI/> 

21* **Source code and issues:** <https://github.com/jacobwilliams/VibeFPMGUI> 

22* **fpm:** <https://fpm.fortran-lang.org> 

23* Tools it uses: [fortls](https://fortls.fortran-lang.org) (language server), 

24 [fortitude](https://fortitude.readthedocs.io) (linter), 

25 [fprettify](https://github.com/fortran-lang/fprettify) (formatter), 

26 [Ollama](https://ollama.com) (local AI models), 

27 [pyqtgraph](https://www.pyqtgraph.org) (graph) and 

28 [Pygments](https://pygments.org) (syntax highlighting). 

29 

30## Running it 

31 

32```sh 

33pixi run start # reopens the last project 

34pixi run start path/to/fpm.toml # or a project folder 

35pixi run demo # the demo project in examples/demo 

36``` 

37 

38With pip (Python 3.11+): `pip install .` (add `.[fortran]` for fortls, 

39fortitude and fprettify, `.[ai]` for the Ollama client), then 

40`vibefpmgui [path/to/fpm.toml]`. fpm and a Fortran compiler must be on the 

41`PATH`. The program starts in `vibefpmgui.main_window.main`. 

42 

43The editor tools are optional. Without fortls or fortitude their *View* 

44menu item says "not found" and the feature is off; without fprettify the 

45*Format* button is greyed out; AI review needs Ollama only when you start one. 

46

144## How it fits together 

145 

146* **fpm runs as a child process** (`QProcess`). Its output goes to the 

147 *Output* panel and is parsed line by line for the *Build* tab. fpm only 

148 prints compiler output when a compile fails, so warnings are read from 

149 its per-file `.o.log` files. 

150* **Tests and programs run through `vibefpmgui.test_runner`**, which fpm 

151 calls for each one (`--runner`). The markers it prints tell the *Tests* 

152 and *Run* tabs where each starts and ends and how it exited. For tests 

153 run in parallel, it only reports each test's command line 

154 (``--collect``), and `vibefpmgui.parallel_tests.ParallelTests` runs them. 

155* **The editor's Fortran features use separate programs:** fortls (a 

156 long-running language server, see `vibefpmgui.lsp.LspClient`), fortitude 

157 and fprettify (run on the editor's text through stdin), and Ollama (over 

158 HTTP, on a worker thread). None of them blocks the window. 

159* **Settings** are stored with `QSettings`, some per project (keyed by the 

160 manifest's path). Set the `VIBEFPMGUI_SETTINGS` environment variable to an 

161 `.ini` path to use a separate settings file, e.g. for testing. 

162 

163## Development 

164 

165```sh 

166pixi run ruff check . # lint the code 

167pixi run test # the tests (pytest + pytest-qt; no windows appear) 

168pixi run coverage # the same, with a code coverage report in web/coverage 

169pixi run docs # these API docs, into web/api 

170pixi run docs-serve # the same, live in the browser 

171``` 

172 

173The tests in `tests/` drive the real windows with 

174[pytest-qt](https://pytest-qt.readthedocs.io), using Qt's offscreen platform 

175(so they also run on CI machines without a display) and a settings file of 

176their own (your settings are never touched). To watch them run, set 

177`QT_QPA_PLATFORM=cocoa` (macOS), `xcb` (Linux) or `windows`. CI runs them on 

178every push and publishes the [test coverage report](../coverage/index.html) 

179(which lines of the code the tests run) next to these docs. 

180 

181Docstrings are Markdown with Google-style sections (`Args:`, `Returns:`, 

182`Raises:`); a name in backticks, such as `vibefpmgui.lsp.LspClient`, 

183becomes a link here.
