A desktop home for your
Fortran projects

VibeFPMGUI is a graphical front end for the Fortran Package Manager. Build, run and test with live progress, explore your dependencies as a graph, and edit Fortran with a language server, linting, formatting and an AI reviewer that runs entirely on your machine.

Build

Watch every file compile

Run fpm build, run, test, update and clean from the toolbar, with the usual options — profile, compiler, flags, features, target and arguments. Hover an option to see the fpm flag it becomes.

  • A live grid of every file and target fpm compiles — parallel and OpenMP builds included — with status, package and time, plus overall progress.
  • Warnings come from fpm's per-file compiler logs, so you see them even when the build succeeds. gfortran, gcc/clang, Intel and lfortran messages are understood.
  • Double-click a row to open the source at the first message; right-click for the exact compile command.
  • Coloured compiler output is shown in colour, and runaway output (100+ MB) can't freeze the app.
  • Pick features and profiles from the project's own fpm.toml.

Test & run

Tests you can follow

Test builds, lists the tests, then runs each one through a small wrapper so its start, end and exit code are known — even with your own --runner such as mpirun.

  • Every test as queued, running, passed or failed, with its time and a progress bar.
  • Run times are remembered, so later runs estimate the time left.
  • Click a test to see only its output. Run works the same way for programs.

Dependencies

See how it all fits together

The dependency diagram is built from your fpm.toml and those of every downloaded dependency — git, local path, registry and metapackages, with dev dependencies dashed.

  • Layered, radial, circular or force-directed layouts; light, dark, blueprint and neon themes.
  • Click a package to highlight what it uses and what uses it; double-click to open its manifest.
  • Git dependencies show the exact commit fpm checked out, linked to GitHub or GitLab.
  • Check for Dependency Updates finds newer tags without downloading anything, and updates a pin in place.

Project files

Your project, and everything it pulls in

The file tree lists the project and each dependency, with fpm's folders badged — library sources, programs, tests, examples, include files.

  • Hidden, generated and git-ignored files are greyed out, with the responsible .gitignore line.
  • A fast filter, even on projects with tens of thousands of files.
  • Files with errors or warnings from the last build show in red or orange.
  • The Build outputs tab shows every build configuration fpm has kept, with its programs and tests ready to run — and a way to free the space.

Editor

A Fortran editor that knows your code

Double-click a file — or a row in the build grid — and it opens in the built-in editor, with the build's warnings and errors in the gutter. Open tabs, cursor positions and the file tree are remembered per project.

Hover cards

Rest on a name for its declaration and doc comment. Intrinsics get their full manual page, rendered, with a badge and their category.

Linting as you type

fortitude checks the text in the editor — saved or not. Findings are underlined and marked in the gutter, with the rule and the suggested fix.

One-click formatting

fprettify re-indents and re-spaces the file, as a single Undo step.

Language server

Navigate and refactor with fortls

The editor talks to fortls, which indexes your project and its dependencies — only fpm's own folders, so a Python environment inside the project doesn't get in the way.

Completion

After two letters, or a % for a type's components — your names, your dependencies' and the intrinsics.

Argument hints

Typing a call shows its arguments, the current one underlined, with its declaration and documentation.

Outline

The file's modules, types and procedures, with a badge for each kind; it follows the cursor.

Find references & go to definition

F12 or ⌘-click jumps to a definition — even inside a dependency — and back again. ⇧F12 lists every use, grouped by file. ⌘T finds any symbol in the project.

Rename with a preview

F2 renames a name everywhere it's used, after showing every line that will change. Open files change in the editor (one Undo); dependency files are left alone unless you tick them.

AI review

A second pair of eyes, on your own machine

AI → Review Current File sends the file in the editor — and its compiler messages — to a model running locally through Ollama. No code is sent anywhere, and once the model is downloaded it works offline.

  • Findings stream into a table — click one to jump to the line — and are marked in the gutter.
  • Pick any installed model (default qwen2.5-coder:7b) and a focus: bugs, modern style, performance or documentation.
  • The app starts the Ollama server when it's needed and stops it when you quit.

Make it yours

Any Pygments colour style

View → Syntax Colours offers every installed Pygments style, light or dark — or follows your system automatically. Text size, graph theme and layout are yours to choose too.

Get started

The easiest way is pixi: one environment with fpm, gfortran, fortls, fortitude, fprettify and Ollama.

With pixi
# get the code
git clone https://github.com/jacobwilliams/VibeFPMGUI
cd VibeFPMGUI

# start it (reopens your last project)
pixi run start
pixi run start path/to/fpm.toml

# try the demo project
pixi run demo
With pip (Python 3.11+)
pip install .            # the app
pip install .[fortran]   # + fortls, fortitude, fprettify
pip install .[ai]        # + the Ollama client

vibefpmgui path/to/fpm.toml

fpm and a Fortran compiler need to be on your PATH. For AI review, install Ollama; the app offers to download the model the first time.

The demo project in examples/demo uses features, profiles, git, path and metapackage dependencies, warnings, parallel compiles and tests — so every part of the app has something to show.
